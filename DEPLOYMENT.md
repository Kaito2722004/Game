# Deploying online

> မြန်မာဘာသာ: [DEPLOYMENT.my.md](DEPLOYMENT.my.md)

Three pieces, three hosts, all on free tiers:

```
  Browser
     │
     ▼
  Vercel ─────────► Render ─────────► Neon
  React app        FastAPI API       PostgreSQL
```

They must be set up in this order, because each one needs a URL or a
connection string from the previous step.

---

## Before you start

You will create accounts on three sites. Sign up with GitHub on all three and
it takes a couple of minutes:

- <https://neon.tech> — database
- <https://render.com> — backend
- <https://vercel.com> — frontend

Keep a scratch file open. You will collect three values:

| Value | Comes from | Looks like |
|---|---|---|
| Database URL | Neon | `postgresql://user:pass@ep-xxx.neon.tech/db` |
| API URL | Render | `https://prisoners-dilemma-api.onrender.com` |
| Frontend URL | Vercel | `https://your-project.vercel.app` |

---

## Step 1 — Database on Neon

1. Create a project. Any name; pick the region closest to you.
2. Open **Connection Details** and copy the connection string.
3. **Edit it into the form this project needs.** Neon gives you
   `postgresql://…`; SQLAlchemy needs the driver named and SSL required:

   ```
   postgresql+psycopg://USER:PASSWORD@HOST/DBNAME?sslmode=require
   ```

   Only two edits: `postgresql://` becomes `postgresql+psycopg://`, and
   `?sslmode=require` goes on the end if it is not already there.

Nothing else to do here. The tables are created automatically in step 2.

---

## Step 2 — Backend on Render

1. **New → Web Service**, connect the GitHub repository, choose branch `main`.
2. Render reads [`render.yaml`](render.yaml), so the build and start commands
   are already filled in. Leave them alone.
3. Set the environment variables it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the edited Neon string from step 1 |
   | `FIRST_ADMIN_EMAIL` | your email |
   | `FIRST_ADMIN_PASSWORD` | **a real password you choose** |
   | `CORS_ORIGINS` | `https://placeholder.vercel.app` — a temporary value, replaced in step 4 |

   `SECRET_KEY` is generated by Render; do not set it yourself.

   The placeholder matters: the app refuses to start with an empty
   `CORS_ORIGINS`, and the real frontend URL does not exist yet. Any
   valid URL gets the first deploy through; step 4 corrects it.

4. Deploy. The first build takes a few minutes. On boot it runs the migrations
   and the seed automatically, so the tables, the six strategies, the default
   payoff matrix and your admin account all appear.

5. Check it: open `https://YOUR-API.onrender.com/docs`. Swagger should load.

> **The app refuses to start if `SECRET_KEY` is still the built-in default or
> `CORS_ORIGINS` is empty**, and the seed refuses to create an admin using the
> default password. Both of those values are published in this repository, so
> a deployment using them would be open to anyone who read the source. If the
> deploy fails, read the log — it names exactly what is missing.

---

## Step 3 — Frontend on Vercel

1. **Add New → Project**, import the same repository.
2. **Set the Root Directory to `frontend`.** This is the step people miss —
   without it Vercel looks for `package.json` in the repository root and the
   build fails.
3. Framework preset: Vite. The rest comes from
   [`frontend/vercel.json`](frontend/vercel.json).
4. Add one environment variable:

   | Variable | Value |
   |---|---|
   | `VITE_API_BASE_URL` | `https://YOUR-API.onrender.com/api/v1` |

   The `/api/v1` suffix matters. Without it every request 404s.

5. Deploy, and note the URL you get.

---

## Step 4 — Introduce them to each other

Go back to Render, set `CORS_ORIGINS` to the Vercel URL, and save:

```
CORS_ORIGINS=https://your-project.vercel.app
```

No trailing slash. Render restarts on its own.

Without this the browser blocks every request, and the frontend shows
"Unable to connect to the backend" even though the API is healthy.

---

## Step 5 — Check it end to end

Open the Vercel URL and confirm:

- [ ] The sign-in page appears
- [ ] Signing in with your admin email and password works
- [ ] **Strategies** lists six strategies — proves the API and database are wired
- [ ] **Payoff Matrix** shows the Nash badge on DD — proves the analysis engine runs
- [ ] Creating and running a tournament produces a ranking table
- [ ] Reloading a deep link such as `/history` still works, rather than 404ing

## Things that will surprise you

**The free Render service sleeps.** After 15 minutes of no traffic it spins
down, and the next request takes roughly 50 seconds to wake it. In the
meantime the frontend shows the "backend unreachable" state.

For a presentation, **open the API URL five minutes beforehand** so it is
already awake. This is the single most likely thing to go wrong in front of
your teacher.

**Two different databases.** Your laptop still has its own local PostgreSQL.
The deployed site uses Neon. Data does not move between them — a tournament
run locally will not appear online, and vice versa.

**Every visitor shares one database.** Anyone with the link can read the data,
and anyone who signs in can add to it. Fine for coursework, worth knowing.

**Big tournaments.** A six-strategy, 100-round tournament takes about
0.04 seconds, so the free tier handles it comfortably. Very large repetition
counts are slower and may hit a request timeout; if that happens, reduce
`repetitions` rather than rounds.

---

## Running locally afterwards

Nothing about deploying changes local development. `.env` is gitignored and
still points at your local PostgreSQL, so the two commands are unchanged:

```bash
uvicorn app.main:app --reload
```

```bash
npm run dev --prefix frontend
```
